# Acceptance Criteria — Adapter Platform v2

- [x] **AC1 — Registro e capacidades**: Existe um registro tipado de adapters e artefatos com `AdapterCapabilityProfile`; Codex aparece como ferramenta oficial no CLI, setup, detecção, diagnóstico e contrato público.
- [x] **AC2 — Propriedade de artefatos**: A geração é orientada por artefato, não por loop de ferramenta; `AGENTS.md` compartilhado por Codex e OpenCode é renderizado uma única vez e testes provam independência de ordem e ausência de sobrescrita.
- [x] **AC3 — Direção canônica**: Um serviço `AgentDirectionService` produz `AgentDirectionSnapshot` estruturado com revisão, origem, item, stage, papel, spec, AC pendente, permissões, proibições, evidências requeridas e próxima ação, sem inventar dados ausentes no harness.
- [x] **AC4 — Bootstrap nativo do Codex**: O adapter Codex compõe `AGENTS.md`, `.codex/config.toml` e `.agents/skills/letra-harness/SKILL.md`, preserva conteúdo do usuário e instala apenas configuração de projeto necessária à integração.
- [x] **AC5 — Contexto vivo**: `letra mcp serve` oferece consultas read-only ao snapshot, spec e saúde; mudanças de item, stage, AC ou harness aparecem na consulta seguinte da mesma sessão, sem exigir reinício do Codex.
- [x] **AC6 — Operações controladas**: MCP e fallback CLI reutilizam serviços de domínio para validar, registrar evidência, concluir AC e solicitar transição; operações inválidas são rejeitadas e operações aceitas retornam revisão anterior, nova revisão e ID de auditoria.
- [x] **AC7 — Degradação transparente**: Quando o MCP estiver ausente ou indisponível, o adapter orienta o uso do comando JSON equivalente, informa estado degradado e mantém leitura e validação possíveis sem contornar o harness.
- [x] **AC8 — Segurança e observabilidade**: O servidor opera por `stdio`, confina acesso ao workspace resolvido, valida schemas, não aceita caminhos arbitrários nem executa shell interpolado, classifica ferramentas mutantes e registra quem, o quê, quando, por quê e resultado.
- [x] **AC9 — Compatibilidade cross-adapter**: OpenCode consome o novo contrato compartilhado sem regressão e ao menos um adapter legado continua usando projeção estática; o desenho documenta como capacidades adicionais serão adotadas incrementalmente pelas demais ferramentas.
- [x] **AC10 — Evidência e dogfooding**: Testes unitários, de contrato, propriedade, integração MCP e smoke real com Codex comprovam bootstrap, atualização viva, colisão de artefatos, gates, fallback e preservação de arquivos; `letra validate`, typecheck e build são aprovados com riscos residuais registrados.
