# Spec: Design System v2 — Tokens, Radius e Componentes Base

## Outcome

Aplicar a identidade visual oficial do Letra na biblioteca `@letra/ui`, tornando os tokens canônicos, padronizando border radius e redesenhando os componentes base sem perder compatibilidade com shadcn/base-ui.
Tornar `@letra/ui` a implementação canônica do DS v2 do Letra, servindo tanto para consumo web quanto como catálogo/caniuse para agentes de IA.

## Constraints

- Todos os componentes devem vir de `@letra/ui` ou do registry `@shadcn`
- Nenhum elemento HTML raw (`<button>`, `<input>`, `<select>`, `<textarea>`, `<table>`, `<dialog>`, `<details>`) deve ser usado para UI — exceção: elementos semânticos estruturais (`<header>`, `<nav>`, `<main>`, `<aside>`, `<section>`)
- Layout deve usar CSS Grid do Tailwind (`grid-cols-*`, `grid-rows-*`, `gap-*`) em vez de `flex` para estrutura principal
- Manter identidade visual Amber existente (brand manual)
- Build deve passar sem erros
- Acessibilidade WCAG 2.2 AA mantida
- Não remover exports públicos de `index.ts`.
- Não quebrar consumo existente sem migração guiada.
- Não hardcodar cores hexadecimais em componentes; usar tokens.
- Esta spec substitui work ad-hoc anterior; mudanças de escopo devem gerar ADR.
- Próxima fase: catálogo JSON + padrões de composição.

- [x] **AC-RADIUS — Border Radius (Revisado)**:

  - [ ] Componentes no client (`packages/client/src`) que usam `rounded-lg` hardcoded (HomeView, SupervisionInbox, etc.) migrados para token

- [x] **AC-ACCENT — Accent Purple**:

  - [ ] `--accent-foreground` = `var(--color-text-primary)`
